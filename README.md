# 篝合（かがりあい）— Browser FPS Production Candidate rc.5

灯環世界ヴェルソラの5対5ヒーローFPS『篝合』を、ブラウザで遊べるサーバー権威型の Production Candidate として実装しています。

「潮占」1モード・「大潮井」1マップに、表示と衝突を同じ設計図から生成するPBR競技ワールド、18人のキャラクター、固有武器、パッシブ、副攻撃、能力1・2、必殺技、1/2/2ロール編成、空間音響、戦闘エフェクト、状況別ロールガイダンス、ゲームパッド、18人対応ボットを統合しています。ユーザー提供の鉱山GLBはハッシュとライセンスを検証する参照アセットとして保持しますが、構造が競技用衝突と一致しないため不透明メッシュは表示しません。

## 起動

```powershell
npm ci               # 初回のみ
npm start            # http://127.0.0.1:8787
npm test             # シミュレーション・UI・通信・ボットの自動テスト
npm run map:check    # 参照GLBの解析マニフェストが再現可能か検証
npm run headless     # 18人を循環させる複数seedのBO3完走検証
npm run verify       # 上記の自動検証を一括実行
npm run verify:release # verify後、本番設定の一時サーバーでready/10人WS/ACK/pongを検証
```

ブラウザで名前を入力し、18人からキャラクターを選んで「このキャラクターで接続」を押します。音響は最初のクリックで有効になります。マウス感度はスライダーまたは1.0〜200.0の数値で設定でき、ゲームパッド感度も独立して保存されます。

編成は正典どおり、各チーム **篝手1・焔手2・灯手2** に制限されます。準備中のロール変更は対象ロールのBOT枠が空いている場合だけ可能です。

## 18人のロスター

- 篝手（前衛）: ザイル、バラガ、ヴェスタ、ヌエドリ、セドラ、シオマネキ
- 焔手（攻撃）: アサギ、シラサギ、ツバクロ、ホクチ、ボタン、アンコウ
- 灯手（支援）: ツヅリ、コヨミ、カラカサ、シラベ、ヒバリ、カズラ

ザイル、ヴェスタ、アサギ、ツバクロ、ツヅリ、コヨミの6人は凍結済み詳細仕様の数値と中核挙動を優先しています。残る12人は凍結資料の概要にある固有メカニクスを、対戦可能なプロトタイプ挙動として実装しています。

## 実装範囲

- 63Hzのサーバー権威シミュレーションと21Hzスナップショット
- 連続sweepとslideを使う移動衝突、天井・立ち上がり空間・段差・動的扉の判定
- 1つのマップ設計図から生成する、同一形状・同一順序の表示面とサーバー権威衝突
- 即着弾・弾道投射・跳弾・爆発・回復弾・障壁・領域効果
- 3D射線、有限高の障壁・設置物、最短TOI、鏡面跳弾、直撃と爆風の重複防止
- 能力の予兆、クールダウン、固有資源、状態効果、必殺ゲージ
- 18人のキャラクター選択、能力説明、HUD、キルフィード、味方状態表示
- 被弾方向、リロード進捗、死亡中の同ロール内ヒーロー変更、安全スポーンと短時間のスポーン保護
- 色だけに依存しない18種類のシルエット、敵味方別の予兆形状、軽減モーション対応
- CC0のPoly HavenコンクリートPBR、ACES色調、空、影、環境小物、一人称武器
- CC BY 4.0の鉱山GLB（422メッシュ）は参照専用で検証し、競技用衝突と一致しない不透明構造物は表示しない
- 武器種別ごとのオリジナル合成音、HRTF空間定位、命中・被弾・回復・必殺技・目標音
- 発射IDによる散弾・予測/確定音の重複抑止と、重要音を確保する有界ボイス管理
- 人数差・目標・体力・能力準備状況から導く、ロール別のライブ行動ガイダンス
- 5対5の潮占、BO3、延長、サドンデス、ウェーブ復帰
- 18人の役割・能力・必殺技を使うボットと、切断後のボット引き継ぎ
- join / select / inputの検証、10人上限、送信バッファ保護
- 有界FIFO入力、適用済みACK、入力リース、サーバー計測RTTに制限された巻き戻し
- `/healthz`・`/readyz`、CSP等のHTTP防御、Origin制限、message rate上限、graceful shutdown
- 有界particle/tracer pool、DPR・影・エフェクト予算、フレームp95による品質自動降格
- 非root・read-onlyコンテナとCaddy TLS終端のComposeテンプレート

本成果物はローカルおよび単一試合サーバー向けの Production Candidate です。競技用ワールドは、見える構造物と当たり判定を同じ設計図から生成する正体積AABBで構成します。PBR材質は実在素材ですが、専用フォトグラメトリ環境、専用キャラクターモデル、録音Foley、アカウント、マッチメイク、永続統計、アンチチート、DDoS防御は別の制作・運用工程です。FPS基礎の受け入れ条件は [`docs/FPS_COMPLETENESS_SPEC.md`](docs/FPS_COMPLETENESS_SPEC.md)、マップ作成は [`docs/MAP_AUTHORING.md`](docs/MAP_AUTHORING.md)、外部アセットの採用候補と権利ゲートは [`docs/EXTERNAL_ASSET_SOURCES.md`](docs/EXTERNAL_ASSET_SOURCES.md)、公開手順は [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md) を参照してください。

## 設計原則

- ダメージ、体力、能力、CD、目標、勝敗はサーバーが確定する。
- ヒーロー定義と調整値をデータに集約し、UI・ボット・通信が同じ定義を参照する。
- クライアントは自機移動を予測し、他プレイヤーと能力効果をスナップショットから補間する。
- 凍結済みの数値・用語は `docs/` を正典とし、プロトタイプ簡略化は報告書へ明記する。
- 演出・音響・ガイダンスはpresentation-only moduleとし、サーバー権威判定へ逆流させない。
