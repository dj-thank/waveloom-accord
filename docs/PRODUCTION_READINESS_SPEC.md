# 『篝合』Production Candidate 仕様

## 目的

既存の 5v5 ヒーロー FPS を、ローカル試作から、公開環境へ安全に配置してプレイテストできる Production Candidate へ引き上げる。対象は「質感・音・演出」「操作性と判断支援 UI」「編成ルール」「配信・監視・終了処理」である。

この段階の完成は、ブラウザだけで試合開始から終了まで遊べ、18 ヒーローの固有武器・通常能力・必殺技を使え、サーバーが不正な編成や接続を拒否し、運用者が死活状態と配布物を検証できることを意味する。

## 解決する問題

- ワールドが灰色の試作用形状に見え、武器ごとの音・反動・命中演出の差が弱い。
- マウス感度を厳密な数値で合わせられない。
- 能力の効果と CT は見えるが、いまの役割・局面・次の行動が分かりにくい。
- 正式な 5 人編成がサーバーで保証されず、チームの責務が崩れ得る。
- 静的配信・WebSocket・死活監視・安全な停止・リバースプロキシ構成が本番向けに定義されていない。

## 確定仕様

### 試合とロール

- 5v5、2 ラウンド先取、各ラウンド 240 秒、SETUP 30 秒は frozen 仕様を継承する。
- 各チームは篝手 1、焔手 2、灯手 2で固定する。
- 初回参加時は、選択ロールの BOT 枠と置換する。満員ロールは `role_full` で拒否する。
- SETUP 中のロール変更は、選択先ロールの BOT と現在ロール枠を交換する。
- ACTIVE 中は同じロール内のヒーロー変更だけを許可し、ロール変更は `role_change_locked` で拒否する。
- サーバーを権威とし、クライアント側の無効化表示だけに依存しない。

### 視覚品質

- 色空間、フィルミックトーンマッピング、フォグ、動的な空と水、影、表面テクスチャ、地形オブジェクトを用いる。
- 一人称武器モデル、マズルフラッシュ、反動、命中・撃破・能力エフェクトを表示する。
- パーティクル数と DPR に上限を設け、軽量端末や reduced-motion 設定を尊重する。
- 競技用の床・壁・遮蔽は共有blueprintから表示面とサーバー権威AABBを同時生成し、片方だけを変更できないようにする。
- CC0のPoly Haven PBR材質をハッシュ付きで読み込み、失敗時はbundle単位でプロシージャル材質へ安全にフォールバックする。
- ユーザー提供の `chicken gun fruzer mine` GLBは、CC BY 4.0の作者表示とハッシュを保持した装飾・参照レイヤーとして読み込み、競技用衝突を追加・置換しない。

### 音響

- 武器種ごとに発射音の輪郭を分ける。近接、精密、ライフル、爆発、散弾、誘導、ビーム、設置、回復弾を識別可能にする。
- 発砲・被弾・命中・撃破・回復・能力予告・必殺技・目標状態を音で伝える。
- 3D 音源には HRTF パンニングを使い、AudioContext はユーザー操作まで生成しない。
- 音の有効／無効と主音量を保存し、0% も正しく保持する。

### 操作と戦闘 HUD

- マウス感度は 1.0〜200.0 を 0.1 刻みのスライダーと数値入力の両方で設定する。
- 選択ヒーロー、ロール、武器名、武器特性、HP、シールド、弾数、固有資源を表示する。
- 各能力は効果、キー、状態、CT、必殺技ゲージを表示する。
- 下部 UI はロール目的、現在局面、推奨行動、実行可能な能力を動的に示す。
- 推奨行動は SETUP、死亡、低 HP、人数差、目標争奪、優勢・劣勢を優先順位付きで判定する。

### 本番運用

- Node.js 20 以上で起動し、`NODE_ENV=production` では `KAGARIAI_PUBLIC_ORIGIN` を必須とする。
- HTTP は GET/HEAD のみ許可し、CSP、nosniff、COOP、CORP、Referrer-Policy、Permissions-Policy を付与する。
- WebSocket は許可 Origin、最大ペイロード、秒間メッセージ数、ping/pong を検証する。
- `/healthz` と `/readyz` は protocolVersion、稼働時間、接続数、tick drop を返す。
- SIGTERM/SIGINT では readiness を落とし、接続へ再起動を通知して猶予時間内に停止する。
- Docker イメージは非 root、Compose は read-only filesystem、capability drop、healthcheck を使う。

## ユーザーストーリーと受け入れ条件

1. プレイヤーとして、1/2/2 のチームで役割を理解して戦いたい。満員ロールは UI とサーバーの双方で選択できない。
2. プレイヤーとして、普段の感度を正確に合わせたい。数値とスライダーが双方向同期し、再読込後も保持される。
3. 初心者として、次に何をすべきか知りたい。役割目的・局面・一文の推奨行動が常時更新される。
4. プレイヤーとして、武器差を視覚と音で感じたい。武器種別の短い特性と固有の音響プロファイルがある。
5. プレイヤーとして、能力と必殺技を判断して使いたい。全スロットの効果、キー、CT、状態が読める。
6. プレイヤーとして、攻撃の結果を即座に知りたい。発砲、命中、被弾、撃破、回復に対応する演出がある。
7. プレイヤーとして、低性能端末でも遊びたい。描画負荷が上限管理され、reduced-motion で演出を抑える。
8. 運用者として、正しい公開 Origin 以外を拒否したい。本番起動は Origin 未指定で fail closed する。
9. 運用者として、サービス状態を監視したい。health と readiness の状態コードと JSON が機械判定できる。
10. 運用者として、安全に更新したい。SIGTERM で新規受け入れを停止し、接続を閉じて終了する。
11. 運用者として、再現可能に配布したい。固定依存のコンテナ、Compose、Caddy 例、手順書、ハッシュ付き成果物がある。
12. 開発者として、仕様回帰を防ぎたい。ルール、UI 契約、音響、描画、本番設定、配備契約の自動テストが通る。

## 検証計画

- `npm test`: ユニット、統合、DOM 契約、描画契約、配備契約。
- `npm run headless`: 18 ヒーローを含む複数試合の決着と例外ゼロ。
- `npm run smoke -- --url ws://127.0.0.1:8787`: 10 接続、11 人目拒否、満員ロール拒否、入力 ACK、ping/pong。
- HTTP: `/healthz` と `/readyz`、CSP、cache、nosniff を確認する。
- 実ブラウザ: 選択、感度、音量、参加、HUD、描画、コンソールエラーを確認する。
- `git diff --check`、Node 構文確認、配布 ZIP の SHA-256 を記録する。

## 非対象と品質境界

- 写実的なスキャン済みマップ、モーションキャプチャ、収録済み銃声、AAA 級キャラクターアニメーションは別のアセット制作工程とする。
- アカウント、永続マッチメイキング、ランキング、観戦、チート対策基盤、地域分散、オートスケールは含めない。
- 公開 DNS、TLS 証明書、ホスティング先への実デプロイは、運用者が対象ドメインと実行環境を指定した後に行う。
- したがって本成果物は「ローカルのクローズドプレイテスト用 Production Candidate」であり、公開DNS/TLS、対象ホストE2E、P1ネットワーク試験、ソース配布ライセンス決定を終えるまでは「世界公開版」「商用ライブサービス完成」「AAA アセット完成」とは表現しない。
