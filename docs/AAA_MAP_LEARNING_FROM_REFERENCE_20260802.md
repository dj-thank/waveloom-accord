# 参照マップから学ぶ — 大潮井をAAA品質へ運ぶ実行計画（2026-08-02）

この文書は「何をすればいいか」「どういう風にすればいいか」を、参照マップ
（`C:\Users\rambo\Downloads\SURAVASA`）の**測れる設計値だけ**から導いた計画である。

## 0. 方法と境界

参照からはジオメトリ・テクスチャ・マテリアル・オブジェクト名・レイアウトを一切
取り込まない。取り出したのは headless Blender で測った**抽象的な統計値**（個数・
寸法分布・空間勾配・階層・近接間隔）だけで、実装はすべてオリジナルで書く。これは
`OSHIOI_PRESENTATION.authorship.referencePolicy = 'abstract-quality-benchmark-only'`
と `prohibitedMotifs`（suravasa-layout / -architecture / -textures / -meshes）に整合する。
参照は寸法の物差しであって、写す対象ではない。

ドーム（丸屋根）は参照の支配的モチーフだが**採用しない**。実在文化の様式禁止という
本プロジェクトの規則が上位にある。曲面は barrelRoof（半円筒）と cylinder で出す。

## 1. 実測した gap（参照 vs 現状のプレイ領域 |x|≤64, |y|≤48）

| 指標 | 参照 | 大潮井 | 意味 |
|---|---:|---:|---|
| 1インスタンスあたり三角形 | **387** | **18** | 21倍差。ここが「色付きグレーボックス」の正体 |
| 塊のアスペクト flat/upright/tower | 49 / 34 / 17 | 70 / 16 / 12 | 参照の flat は屋根・軒・蛇腹（立体）、うちの flat は舗装の板（デカール） |
| 2m以下の小物の割合 | 51% | 90%※ | ※うちは薄い舗装板が水増し。実体のある小物детはほぼ無い |
| 立体（h>1.2m）の近接間隔 中央値 | 2.37m | 0.41m | うちは**密すぎる**。少数の宿主に被覆を過剰に貼っている |
| 立体の近接間隔 p90 | 6.94m | 2.10m | 参照は「離れた個体が多数」、うちは「1棟に集中」 |
| 垂直方向のインスタンス分布 | 0→16m の滑らかな山 | z=4 に48%が集中、上は薄い | 参照は全高に連続、うちは床に一極集中 |
| 遠景スカイライン | z 146〜947 の独立層 | あり（barrel/spire）| ここは既に良い |

### この表から読み取れる3つの構造的事実

1. **三角形/個が21倍違う（387 vs 18）のが最大の差。** インスタンス数（19,059 vs
   16,322）は既に上回っている。density の問題ではなく、1個1個が箱と板であることの
   問題。三角形予算は 527k/1,200k で44%しか使っておらず、約67万の余地がある。

2. **近接間隔が逆に密すぎる（0.41m vs 2.37m）。** これは前回判明した「港湾街区が
   23棟しか無い」ことの裏返し。少ない宿主に何千枚も被覆を貼って density を
   演出している。参照は richness を**多数の離散したオブジェクト**に分散している。
   → 被覆を増やすのではなく、**宿主（建物・地物）の数を増やす**のが正しい。

3. **垂直分布が床に一極集中（z=4 に48%）。** 参照は 0〜16m に滑らかな山を描く。
   うちは市場床（z=4）に半分が乗り、その上が急に薄くなる。目線の高さ（1.6m）〜
   全身遮蔽帯（〜2.9m）の情報が足りず、立って歩くと「床の模様は濃いが、体の
   周りは空いている」と感じる。

## 2. 参照の地形・空間構成から学んだこと（4枚のレンダーと統計から）

### 2.1 三層の奥行き（sur1〜sur4 に共通）

- **近景 = ヒーロー建築。** 巨大で彫りが深く、段状のシルエットで画面を支配する。
  壁は平面ではなく、基壇→胴→蛇腹→軒→冠の水平帯と、凹んだ開口パネルを持つ。
- **中景 = 密集した低い塊 + 樹木。** ドームと低い建物が絡み合い、その間を
  **大樹冠の樹木が地面レベルで**縫う。屋上緑化ではなく、歩く高さの木。
- **遠景 = 独立したスカイライン。** 金の超高層（統計で z 350〜947）が霞んで立つ。
  プレイ帯（z 0〜40）とは完全に分離した層。

うちは近景のヒーロー建築が弱い（中央塔はあるが、街区の建物が小さく単調）、
中景の地上樹木がゼロ、遠景は既に良い。

### 2.2 地形（terrain）の扱い

- 参照の「大きな平面」は**わずか5枚**（span 最大2965単位）。地形そのものは
  少数の大メッシュで、richness は地形ではなく**その上に載る無数のオブジェクト**で
  作っている。地面を細かく割っているわけではない。
- 自然物（岩・丘・樹木）が人工物の**縁**に置かれ、硬い境界を和らげている
  （sur2 の中庭、sur3 の右の丘、sur4 の岩と樹叢）。
- 水路が negative space として街区を分け、可読性（どこが通路か）を上げている。
  うちの `ground-tide-canal` は14枚しかなく、中央窪地だけ。参照のように街区の
  合間に水を通せば、射線分割と可読性が同時に上がる。

### 2.3 richness の作り方（統計）

- 2m以下の小物が**51%（約8,300個）**。これが「近づくと細部が湧いて出る」感覚の
  母体。ポット・段・ブラケット・小さな祠・手すり子・幟。うちにはこの層が実体として
  ほぼ無い（薄い板で水増ししているだけ）。
- 近接間隔の中央値2.37m ＝ おおむね腕の届く距離ごとに離散したオブジェクトがある。
  p10 が0.09m ＝ 壁に載る蛇腹、棚の上のポットのように**触れ合う多層の細部**もある。

## 3. やることリスト（優先順・HOW付き）

各項目に「なぜ効くか」「どう測るか」「触るのは当たり判定か描画か」を明記する。
当たり判定に触るものは、コア樹木が落ちたのと同じ
`tests/hero_bots.test.js` の mirrored-matchup バランスゲートを必ず通す。

### P0-A. 港湾街区の候補グリッドを作り直す（当たり判定／最大の一撃）

**なぜ:** 前回判明した通り、`tryStore` は候補を117個しか生成せず、コメントの
「178棟」に構造的に到達不能。壁が23棟しか無いので、壁・屋根・アーチ・軒の語彙が
どれも効かない。近接間隔が参照の逆（0.41 vs 2.37）なのも、少数宿主への過剰被覆が原因。

**どう:**
1. `BLOCK_PITCH_X/Y`（23/21）を詰める、または街区の間に infill ユニットを挿す。
   候補を117→300以上へ増やし、既に合法な空間の中だけで密度を上げる。
2. 各ユニットの寸法を3スケール（小屋 4〜6m / 中 7〜10m / 大 11〜16m）で散らす。
   参照の footprint 分布（4〜8mが最頻）に寄せる。
3. `routeClear` は緩めない（前回、緩めても23→28にしかならず割に合わないと実証済み）。
   代わりに候補を増やして「合法な隙間」を全部使う。

**測る:** `ring-store-*` を23→80以上。その後 `three competitive matchups`（固定
シード mirrored）と `audit_route_safety`（30/30）、`audit_fake_cover_clusters`（0）を
必ず通す。バランスが崩れたら配置を反復。**当たり判定なのでバランスゲートが最終判定。**

### P0-B. 目線帯（z 4.5〜7.0）へ立体ディテールを足す（描画のみ）

**なぜ:** 垂直分布が z=4 に48%集中し、立って歩く高さ（床+1.6〜3.0m）が薄い。
参照は全高に連続。ここが「床は濃いが体の周りは空く」感覚の原因。

**どう:** 既存の被覆モジュール（`inner` / `slab` / `bracketModule`）で、宿主上端
より下の**胴体帯**に水平の蛇腹・窓台・軒下ブラケットを増やす。宿主 footprint 内
なので偽の遮蔽にならない（`fake-cover` 規則の対象外）。box ではなく、蛇腹は
chamferBox（44三角形）、開口は archWall（218三角形）を使い、tris/個 を底上げする。

**測る:** z 4.5〜7.0 帯のインスタンスを現状比 +50%。`map_site_cladding` 全テスト、
`audit_fake_cover_clusters`（0）、実画面ドローコール ≤250、三角形 ≤1,200,000。

### P1-A. 垂直材・軒・冠を box → 曲面に置換して三角形を投下（描画のみ）

**なぜ:** tris/個 18 vs 387。予算は67万余っている。シルエットを決める要素
（柱・軒・冠・開口）を曲面化すれば、同じインスタンス数のまま「箱」感が消える。
今セッションで `core-pilaster` を box→cylinder 済み（+15,932三角形、効果を実画面で確認）。

**どう（順に）:**
1. `clad-shell-trim`（747個）のうち垂直材を cylinder へ。
2. 軒・蛇腹を chamferBox（角を落とした押し出し、44三角形）へ。
3. 冠・頂華を spire/barrelRoof へ（既存 primitive、dome は使わない）。
4. 大きな開口を archWall（218三角形）へ。1個あたりの投下効率が最も高い。

**測る:** tris/個 を 18→40以上（参照の1/10でも見違える）。三角形 ≤1,200,000、
ドローコール ≤250、`map_layer_budget` テスト。

### P1-B. 地上の樹木をレーン外へ（当たり判定／バランス反復）

**なぜ:** 参照の中景は地上樹木が主役。うちは中央コアに木が0本。前回コア中央へ
6本入れたら mirrored-matchup が 1:6 / 5:0 に崩れた（性能ではなくバランスが原因と実証）。

**どう:** コア中央（射線が集中する制圧点まわり）は避け、**レーンの外側の袋小路・
壁際・段の陰**に、180度対称を厳守して1〜2対ずつ置く。1対ごとにバランススイートを
回して、崩れない位置だけを残す。当たり判定は既存 `ring-tree-*` の仕組みをそのまま使う。

**測る:** `three competitive matchups` 固定シードで一方性が出ないこと。1対追加ごとに
検証（1周約10分）。崩れたら即revert。

### P1-C. 街区の合間に水路を通す（描画のみ、可読性）

**なぜ:** 参照は水路で街区を分け、通路と非通路を一瞥で分ける。うちの
`ground-tide-canal` は中央窪地の14枚だけ。

**どう:** 港湾街区（リング帯）の建物の**間の歩けない隙間**に `wetRock`/`tideGlow` の
板を敷く。歩ける経路には敷かない（経路データと交差判定）。層は既存を流用。

**測る:** 可読性は人間レビュー項目だが、自動側では経路30/30が不変であること、
ドローコール ≤250 を守る。

### P2. 色相の集約（描画のみ）

**なぜ:** 参照は暖色1系統＋金のほぼ単色で、拠点ごとの差は明度と彫りで出す。うちは
teal/blue/white/orange が散り、統一感が弱い。

**どうः** マテリアル定義（`map_oshioi_presentation.js` の materials）を触るので影響が
広い。まず対象材質と範囲を1つに絞る（例: `roofBlue` の彩度を落として暖色寄りに）。
テストが材質名を固定しているので、変更前に依存テストを洗い出す。

**測る:** `map_visual_finish` / `map_quality_score` の視覚階層テスト、実画面の
パレット監査（`audit_palette`）で暖色/金の面積比。

## 4. 進め方（1ループの型）

各変更は次を1ループとする。SURAVASA参照はステップ0の物差しとしてのみ使う。

0. 参照の該当指標を確認（この文書の§1表）。目標値を決める。
1. 対象ファイル・受け入れ条件・触るのが当たり判定か描画かを書く。
2. 実装（オリジナル。参照のジオメトリ/名称は使わない）。
3. 局所テスト → 全体テスト（875）→ `git diff --check`。
4. **当たり判定を触ったら必ず** `three competitive matchups`（固定シード）を
   **負荷なしで**測る。headless の `--max-wall-sec` は実時間なので、裏で Chrome を
   回したまま測ると偽陽性が出る（今セッションで実証済み）。
5. 実画面を撮る（`capture_map_views`）。ドローコール ≤250・三角形 ≤1,200,000 を確認。
6. 証跡・hash・handoff を更新。結果と未検証範囲を記録。

## 5. 優先順位の根拠（どれから何故）

1. **P0-A（街区グリッド）を最初に。** これが全ての土台。壁が23→80になれば、
   P0-B・P1-A・P1-C の効果面積が3倍以上になる。単独で最大のシルエット改善。
2. **P0-B（目線帯）と P1-A（曲面化）を次に。** どちらも描画のみで安全、三角形
   予算を使ってグレーボックス感を直接消す。P0-A の後なら効果が街区全体に乗る。
3. **P1-B（地上樹木）はバランス反復が要るので独立で。** 性能は問題ないと実証済み、
   残るはレーン外配置の探索。
4. **P1-C・P2 は仕上げ。**

## 6. 変わらない不変条件

- `canonical-*` と `flash-*` の当たり判定は変更しない。追加は `ring-*` のみ。
- 近接 cladding を無衝突の body-height cover として束ねない（`audit_fake_cover_clusters`=0）。
- 経路30/30を塞がない。高台への2方向登りを保つ。
- candidate音声・画像候補を runtime へ勝手に昇格しない。
- 参照からジオメトリ・テクスチャ・名称・レイアウトを取り込まない。ドームを使わない。
- 当たり判定を触る変更は mirrored-matchup バランスゲートが最終判定。
