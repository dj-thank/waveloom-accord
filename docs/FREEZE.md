## 凍結ルール

1. 矛盾の修正のみ許可する。新機能の追加は禁止。
2. 数値の変更はプレイテストの計測結果を根拠とし、変更理由・期待する結果・監視指標を記録する（±30%の調整余地は設計書の前提のとおり）。ただし比率関係「撃破時間＞反応時間」は不変条件。
3. 名称・用語・ロール呼称（篝手／焔手／灯手）の変更はリード承認を必要とする。
4. モード・マップの数値の唯一の正は `mode_shioura_rules_v0.2_FROZEN.md`。実装・データJSONはこれを転記し、二重管理をしない。

## Phase 2〜3 実装方針（TARGET_ENGINE未指定のための決定）

TARGET_ENGINEが未指定のため、設計書の前提1（エンジン非依存・データ駆動）に従い、**エンジン非依存のリファレンス実装**を採用する:

- シミュレーション核（`shared/`）: 環境非依存の純粋ESMモジュール。移動・射撃・体力・リスポーン・潮占・試合状態遷移をデータ駆動で実装。サーバーとクライアント予測が同一コードを共有する。
- 専用サーバー（`server/`）: Node.js + WebSocket。サーバー権威（63Hz tick）。
- 検証クライアント（`client/`）: ブラウザ + Three.js のグレーボックス。
- Unity/Unreal移植時は `shared/` のロジックと `shared/data/` のJSONを移植元とする。
